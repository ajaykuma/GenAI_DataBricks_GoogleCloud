##Setup another client > mcptest2.py
# - this will run its own instance of MCP server and access tools as requested

#Run mcptest.py and mcptest2.py in parallel

Each client:

> Spawns its own independent server process
> Has its own isolated session
> Gets the same tools registered (since same server script)
> Runs concurrently with no interference

When would this matter in production? If your tools had shared state (like a database counter or cache), 
each client would have its own copy and they wouldn't sync. That's when you'd move to the SSE/HTTP 
transport — one persistent server, all clients share the same state.
For stateless tools like yours (search, calc, weather) — stdio is perfectly fine and simpler to manage.

# mcp_client_1.py
import asyncio
from mcp import ClientSession
from mcp.client.sse import sse_client

async def main():
    async with sse_client("http://localhost:8080/sse") as (read, write):
        async with ClientSession(read, write) as session:
            await session.initialize()

            tools = await session.list_tools()

--Summary:
Terminal 1:  python mcsp_setup.py        ← start server FIRST, keep it running
Terminal 2:  python mcptest.py           ← connects to the server
Terminal 3:  python mcptest2.py          ← also connects to the same server

--The server is now a proper persistent service
  — clients connect and disconnect freely without restarting it.
STDIO (before):                      SSE (now):
Client 1 → spawns Server A           Client 1 ──┐
Client 2 → spawns Server B           Client 2 ──┼──→ ONE Server (port 8080)
(2 isolated processes)               Client 3 ──┘    (shared, persistent)
